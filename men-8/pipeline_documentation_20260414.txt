PHASE 0 — DATASET COLLECTION FROM KEEPA API
================================================================================

WHAT IS KEEPA
  Keepa is a third-party Amazon price tracker that stores historical data for
  millions of products. It exposes a REST API for querying product metadata,
  price history, sales rank history, Buy Box data, ratings, and review counts.
  Amazon does not provide historical sales data directly, so Keepa is used as
  the primary data source.

  API endpoint : https://api.keepa.com
  Domain       : 1 (Amazon US)
  Cost         : 4 tokens per ASIN (1 base + 1 rating + 2 Buy Box)
  Token refill : 20 tokens per minute on paid plan

HOW THE DATA WAS PULLED — 7 BATCH NOTEBOOKS
  The Keepa database for Amazon Shoes (Size 8) was pulled in 7 batches,
  each covering a different sales rank range. This was necessary because:
  - Each Colab session has a limited runtime (~5-12 hours)
  - The Keepa API has token rate limits (20 tokens/minute refill)
  - Splitting by sales rank ensures each batch finishes within one session

  Batch notebooks and their sales rank ranges:

  amazon_shoes_8_batch1.ipynb   Rank       1 –  10,000
  amazon_shoes_8_batch2.ipynb   Rank  10,001 –  20,000
  amazon_shoes_8_batch3.ipynb   Rank  20,001 –  30,000
  amazon_shoes_8_batch4.ipynb   Rank  30,001 –  40,000
  amazon_shoes_8_batch5.ipynb   Rank  40,001 –  60,000
  amazon_shoes_8_batch6.ipynb   Rank  60,001 –  80,000
  amazon_shoes_8_batch7.ipynb   Rank  80,001 – 100,000

  Date window (same for all batches):
    START_DATE = '2025-01-01'
    END_DATE   = '2026-03-31'
    DAYS       = 454

  Output location: demand_modeling_data_8_v2/ on Google Drive
    amazon_shoes_8_batch1.parquet
    amazon_shoes_8_batch2.parquet
    amazon_shoes_8_batch3.parquet
    amazon_shoes_8_batch4.parquet
    amazon_shoes_8_batch5.parquet
    amazon_shoes_8_batch6.parquet
    amazon_shoes_8_batch7.parquet

KEEPA FILTER PARAMETERS (applied in all batches)
  categories_exclude : [679320011, 679365011, 679378011, 679433011]
                       Exclude Costumes, Accessories, and unrelated categories
  title              : 'shoes'           Must contain the word shoes
  rootCategory       : ['7141123011']    Amazon Shoes root category only
  type (exclude ✓)   : sandal, shoelace, slipper
  brand (exclude ✓)  : crocs, flip*flop
  outOfStockPercentage90_BB_gte: 1       Had some out-of-stock time (active)
  outOfStockPercentage90_BB_lte: 80      Not perpetually out of stock
  trackingSince_lte  : 7364640           Anti-backfill guard — Keepa must have
                                         been tracking this ASIN before Jan 2025
  productType        : [0, 1, 2]         Physical products only
  size               : ['8']             Women's size 8 only

  NOTE: The ✓ prefix (unicode 0x271C) before type and brand values is Keepa's
  syntax for excluding those values. So '✓sandal' means exclude sandals.

WHAT EACH BATCH NOTEBOOK DOES
  Input  : Keepa API (live HTTP requests, no local input file needed)
  Process:
    1. Query Keepa Finder API with SELECTION filter to get matching ASIN list
    2. Paginate through all results (100 ASINs per page), cache to .txt file
       (ASIN_CACHE allows resuming if notebook crashes mid-run)
    3. For each batch of 100 ASINs call Keepa Product Data API:
       stats=1, rating=1, buybox=1, offers=0
    4. Expand daily Keepa history into weekly rows:
       window=7  : 7-day rolling average
       window=28 : 28-day rolling average
    5. Apply log transforms:
       SALES_RANK   = log(1 / sales_rank)
       PRICE        = log(avg_price)
       BUYBOX_PRICE = log(avg_buybox_price)
    6. Extract product metadata:
       text     = title | manufacturer | brand | model | color | size
       subcat   = leaf category name from Keepa categoryTree
       image    = first product image URL from imagesCSV
    7. Save to parquet file on Google Drive

  Output columns (27):
    ASIN, window, date, SALES_RANK, PRICE, BUYBOX_PRICE, text, RATING,
    REVIEW_COUNT, subcat, subcat_aggregated, New Offer Count: Current,
    Count of retrieved live offers: New FBA,
    Count of retrieved live offers: New FBM,
    Lightning Deals: Upcoming Deal, Buy Box: Is FBA, image,
    SALES_RANK_original, PRICE_original, BUYBOX_PRICE_original,
    gender, manufacturer, brand, model, color, size

FILE NAMING EXPLANATION (batch notebooks)
  amazon_shoes_8_batchN.ipynb / .parquet
    amazon        = data source platform
    shoes         = product category
    8             = shoe size
    batchN        = batch number 1 through 7
    .parquet      = columnar file format, efficient for large datasets

NOTEBOOK: 00_part1_data_preparation.ipynb
Location: demand_modeling_data_women_8_v2/data_preparation/
================================================================================

INPUT
  demand_modeling_data_8_v2/amazon_shoes_8_combined.parquet
  1,008,930 rows | 7,761 ASINs | 27 columns | Jan 2025 – Mar 2026

OUTPUT
  code/main_train_keys.csv                    ASIN+date for 2,573 train ASINs
  code/main_val_keys.csv                      ASIN+date for 2,574 val ASINs
  data/amzn_shoes_monthly_diffs_ffill_fixed_splits/train-00000-of-00001.parquet
  data/amzn_shoes_monthly_diffs_ffill_fixed_splits/validation-00000-of-00001.parquet

PROCESS
  1. Load combined parquet, parse dates
  2. Remove dirty ASINs:
     wrong gender (Costumes & Accessories, Shoe Jewelry & Watch Accessories),
     wrong size, 100% NaN in SALES_RANK / PRICE / RATING / REVIEW_COUNT
     Total removed: 12 ASINs
  3. Filter to Women only → 5,471 ASINs
  4. Drop 9 unused columns: SALES_RANK_original, PRICE_original,
     BUYBOX_PRICE_original, gender, manufacturer, brand, model, color, size
  5. Fix dtypes: window to float64, FBA/FBM offer counts filled with 0
  6. Rebuild subcat_aggregated from top 10 Women subcategories:
     Pumps, Flats, Fashion Sneakers, Loafers & Slip-Ons, Walking,
     Mules & Clogs, Road Running, Heeled Sandals, Ballet & Dance, Ankle & Bootie
     All others → "Other"
  7. CRITICAL — Fill BEFORE trim:
     Jan/Feb 2025 data acts as forward-fill seed for March.
     BUYBOX_PRICE: ffill then bfill (handles products that gained Buy Box
     during the window — no prior history to carry forward, so bfill
     carries the first known price backward to earlier dates)
     All other columns: ffill only
  8. Trim to analysis window: remove Jan and Feb rows (date >= 2025-03-01)
  9. Create NaN flag columns on trimmed window:
     is_SALES_RANK_filled, is_PRICE_filled, is_BUYBOX_PRICE_filled,
     is_RATING_filled, is_REVIEW_COUNT_filled
     (0 = original value existed, 1 = was NaN and got filled)
 10. Drop incomplete ASINs:
     BUYBOX_PRICE: drop if 100% NaN across full year (92 ASINs — no Buy Box)
     Other columns: drop if any NaN remains after fill
     Total dropped: 324 ASINs | Final: 5,147 ASINs
 11. Reorder to 17-column paper schema, verify dtypes
 12. Stratified 50/50 ASIN-level split by subcat_aggregated (seed=42)
     Train: 2,573 ASINs | Val: 2,574 ASINs | No overlap
 13. Drop NaN flag columns, save parquets and key CSVs

OUTPUT PARQUET COLUMNS (17)
  ASIN, window, date, SALES_RANK, PRICE, BUYBOX_PRICE, text, RATING,
  REVIEW_COUNT, subcat, subcat_aggregated, New Offer Count: Current,
  Count of retrieved live offers: New FBA,
  Count of retrieved live offers: New FBM,
  Lightning Deals: Upcoming Deal, Buy Box: Is FBA, image

NOTEBOOKS: 00_part3a / 3b / 3c / 3d — Embedding Model Training
Location: demand_modeling_data_women_8_v2/data_preparation/
GPU: A100 required | Time: ~1.5–5 hrs per variant
================================================================================

THE 4 VARIANTS (one notebook per variant to fit within Colab session limits)
  Part 3a: txtimg + lag1          Text+Image+Tabular, lag-1 time features
  Part 3b: txtimg + time_ind      Text+Image+Tabular, no lag
  Part 3c: txt + lag1             Text-only, lag-1 time features
  Part 3d: txt + time_ind         Text-only, no lag

INPUT
  data/amzn_shoes_monthly_diffs_ffill_fixed_splits/ (train + val parquets)
  data/images/{ASIN}.jpg  (Parts 3a and 3b only — not needed for txt-only)

MODEL ARCHITECTURE (Bach et al. 2025 Appendix G, Figure 18)
  Text encoder    : RoBERTa (cardiffnlp/twitter-roberta-base) → 768-dim
  Image encoder   : BEiT (microsoft/beit-base-patch16-224) → 768-dim
  Tabular encoder : SAINT (pytorch-widedeep 1.7.0) → 768-dim
  Fusion          : LayerNorm → Cross Attention Block → FC → 256-dim embedding
  Prediction heads: FC → Q_hat (SALES_RANK), FC → P_hat (PRICE)

TRAINING CONFIG
  WINDOW=28, MOD=4, MAX_PERIODS=53, BATCH_SIZE=32
  EPOCHS_LEVEL=25 (predicts Q_t and P_t directly)
  EPOCHS_DIFF=15  (predicts ΔQ_t and ΔP_t — first differences)
  LR=2e-5, EMB_DIMS=[128, 256], Optimizer: AdamW + cosine annealing

OUTPUT (6 zip files per variant = 24 total)
  See predictions/ folder structure above for exact filenames.

  Level model (4 files per variant: 2 emb_dims × 2 splits):
    {split}_pred_model-{DATE}-embdim=None_{lag_type}_{modality}_mod4-
    epoch={E}-val_combined_loss={L}_{modality}_dim={D}_proj_emb_step=.zip

  Diff model (2 files per variant: 1 emb_dim × 2 splits):
    pred_diff_shoes-diff-model-{modality}_{DATE}-embdim=768_lag1-
    epoch={E}-val_combined_loss={L}_{modality}_{lag_or_invariant}_{split}.zip

PREDICTION ZIP FILE NAMING EXPLAINED
  train / val          = which split this file covers
  embdim=None          = dim is set by dim= parameter (level model)
  embdim=768           = internal encoder dimension (diff model)
  time_independent     = no lag features used
  lag1                 = lag-1 time-dependent features
  txtimg               = full multimodal (text + image + tabular)
  txt                  = text-only model
  mod4                 = every 4th time step used
  epoch=018            = best checkpoint epoch number
  val_combined_loss=X  = validation loss at best checkpoint
  dim=128 / dim=256    = embedding projection size
  proj_emb_step=       = paper convention, value intentionally empty
  invariant            = time-independent diff model suffix
  lag1 (in diff name)  = lag-1 diff model suffix

NOTEBOOK: 01_1_create_dataset_txt_img.ipynb
Location: demand_modeling_data_women_8_v2/code/
================================================================================

INPUT
  data/amzn_shoes_monthly_diffs_ffill_fixed_splits/ (train + val parquets)
  All 24 prediction zips via utils/paths_config.yaml
  code/main_train_keys.csv and main_val_keys.csv

OUTPUT
  data/dataset_txt_only_False_embeddings_True_train.zip
  data/dataset_txt_only_False_embeddings_True_val.zip

PROCESS
  1. Load panel parquets (window=28, max_periods=57, every 4th time step)
  2. Create dummy variables for subcat_aggregated and date
  3. Load prediction zips (time_independent emb=256 and lag1 emb=256) via
     load_pred_and_emb() using paths_config.yaml
  4. Join predictions to panel by (ASIN, date)
  5. Compute lag-1 and lag-2 features for Q_t and P_bb_t
  6. Compute first differences: Delta_Q_t and Delta_P_bb_t
  7. Normalize and center 256-dim txtimg embeddings
  8. PCA: reduce to 5 principal components
  9. KMeans: 5 clusters, compute cosine similarity to each centroid
 10. Compute 5 nearest neighbors in embedding space + distances
 11. Compute neighbor-weighted lagged Buy Box prices
 12. Save as zip (compressed CSV inside)

DATASET ZIP FILE NAMING EXPLAINED
  dataset_txt_only_False_embeddings_True_train.zip
    txt_only=False   = full multimodal model (text + image + tabular)
    embeddings=True  = embedding vectors are included in this file
    train            = training split
    .zip             = compressed CSV (pandas zip compression)

================================================================================
NOTEBOOK: 04_evaluation.ipynb
Location: demand_modeling_data_women_8_v2/code/
================================================================================

INPUT
  data/dataset_txt_only_False_embeddings_True_train.zip
  data/dataset_txt_only_False_embeddings_True_val.zip

OUTPUT
  output/04_evaluation/  (ATE and CATE plots)
  ATE estimate with 90% confidence interval
  CATE estimates per cluster
  Chi-squared heterogeneity p-value

PROCESS
  1. Load final dataset, drop lag-2 features and lag-1 predictions
  2. Build basis vectors: subcat dummies + cluster similarities + date dummies
  3. DoubleML Partial Linear Regression (PLR):
       Q_t = theta * P_bb_t + g(X) + epsilon
     theta = causal price elasticity | LightGBM as nuisance learner
  4. Model predictions (pred_ml_l, pred_ml_m) used as price instruments
  5. ATE: average elasticity across all products
  6. CATE: heterogeneous elasticity per cluster
  7. Chi-squared test for heterogeneity (p < 0.05 = significant)

================================================================================
KEY VARIABLE DEFINITIONS
================================================================================

Q_t          = SALES_RANK = log(1/sales_rank) — quantity/demand signal
P_bb_t       = BUYBOX_PRICE = log(buy_box_price) — treatment variable (price)
Delta_Q_t    = Q_t − Q_{t-1}   (first difference of quantity)
Delta_P_bb_t = P_bb_t − P_{t-1} (first difference of price)
window=28    = 28-day rolling average (used for modeling)
mod=4        = every 4th time step kept (approximately monthly)
pred_ml_l    = level model prediction for Q_t
pred_ml_m    = level model prediction for P_bb_t
_diff suffix = diff model prediction for ΔQ_t or ΔP_bb_t
_lag_1 suffix = from lag-1 model variant
emb_0..255   = 256-dim product embedding from fusion model
pca_0..4     = first 5 PCA components of embeddings
similarity_cluster_0..4 = cosine similarity to each KMeans centroid
theta        = price elasticity of demand (key causal estimate)
ATE          = Average Treatment Effect (average theta across all products)
CATE         = Conditional ATE (theta per cluster)


================================================================================
NOTES ON PAPER FIDELITY
================================================================================

Follows Bach et al. (2025) arxiv 2501.00382. Intentional differences:

1. Dataset   : Amazon Women's Shoes Size 8 (Jan 2025 – Mar 2026)
               5,147 clean ASINs after data preparation
               vs Amazon Toy Cars (2023–2024) in original paper
2. Batches   : 7 batches by sales rank range 1 to 100,000
               vs original paper's different batch structure
3. Split     : 50/50 ASIN-level stratified split (advisor recommendation)
               Train: 2,573 ASINs | Val: 2,574 ASINs
               vs 80/20 in original
4. Window    : 57 weekly periods (max_periods=57)
               vs 54 in original (max_periods=54)
5. BUYBOX fill: ffill + bfill for BUYBOX_PRICE
               vs ffill only in original
6. SAINT     : Installed to isolated /content/pkgs with fake gensim injection
               to bypass Python 3.12 conflicts in Colab

Reference repo: github.com/JanTeichertKluge/demand-analysis-repro
